Fonctionnalités

Pourquoi Stackia Telecom ?

Un mesh radio qui marche même quand le reste tombe. Conçu pour être lu, compris et bidouillé.

Sans internet

Aucune box, aucun serveur distant. Les nœuds parlent directement en RF. Le mesh continue de vivre quand le Wi-Fi, la 4G et le cloud sont coupés.

Mesh auto-réparant

Routage par flooding avec TTL, anti-boucle et dédup. Chaque nœud relaie pour les autres : ajoutez-en un, la portée s'étend toute seule.

Pont MQTT & n8n

Les nœuds home antenna font le pont LoRa ↔ MQTT. Automatisez tout depuis n8n : alertes, dashboards, déclencheurs — votre mesh devient programmable.

Web UI embarquée

Une interface servie depuis le nœud (LittleFS) : voisins, messages, statut, envoi. Pas d'app à installer, ça s'ouvre dans le navigateur.

Gros messages

LoRa plafonne à ~200 caractères ? Le firmware fragmente et réassemble automatiquement en base64. Lent mais fiable, pour des Ko entiers.

Config sans code

Au premier boot, un captive portal vous laisse choisir le type de nœud et le Wi-Fi. Sauvé dans /config.json, et c'est parti.

Architecture

Trois rôles, un seul firmware

Le même binaire, trois personnalités. Le type est choisi au premier démarrage.

HANDHELD

Terminal mobile

Un point d'accès Wi-Fi ouvert mesh-{id}. Vous vous y connectez avec un téléphone et discutez via la web UI. Aucun MQTT — c'est le combiné de poche.

  • Wi-Fi : AP ouvert
  • Web UI embarquée
  • Pas de MQTT
Pont

HOME_ANTENNA

Pont LoRa ↔ MQTT

Se connecte à votre Wi-Fi maison (STA) et relaie le mesh vers un broker MQTT local. C'est la passerelle vers n8n, vos dashboards et vos automatisations.

  • Wi-Fi : station (STA)
  • Web UI + MQTT
  • LWT online/offline

REPEATER

Relais + beacon

Wi-Fi désactivé pour économiser la RAM. Il ne fait qu'écouter, relayer et émettre un beacon. Posez-le en hauteur : c'est lui qui étire la portée du mesh.

  • Pas de Wi-Fi
  • Pas de web UI
  • Max de marge RAM

Guide

De la carte au mesh, en 3 étapes

Un ESP8266, un module LR20-A, quatre fils. Pas plus compliqué que ça.

1

Câblez & flashez

Quatre fils entre l'ESP8266 et le LR20-A (3,3 V uniquement). Puis pio run -t upload et uploadfs.

2

Configurez au portail

Au boot, rejoignez l'AP MeshSetup-XXXXXX, ouvrez 192.168.4.1, choisissez le type de nœud. Reboot automatique.

3

Le mesh s'étend

Allumez un deuxième nœud : ils se découvrent par beacon et se relaient. Chaque nœud ajouté agrandit la couverture, sans config.

Sous le capot

Le protocole, à nu

Du JSON compact, du flooding TTL, des topics MQTT clairs. Rien de magique, tout est lisible.

Paquet LoRa (≤ 200 chars)

{
  "f":  "node_01",   // source
  "t":  "node_02",   // destination ou "all"
  "m":  "texte",     // message
  "tp": "msg",       // msg | beacon | ack | frag
  "ttl": 3,          // 1-5, -1 à chaque hop
  "ts": 1234567     // s depuis le boot
}

Flooding : chaque paquet est diffusé en broadcast RF, retransmis tant que ttl > 1, avec un cache anti-boucle des 20 derniers from+ts. Le ts est strictement croissant pour garantir l'unicité.

Topics MQTT (HOME_ANTENNA)

  • RX
    mesh/msg/rx/{id}

    message reçu pour ce nœud / broadcast

  • TX
    mesh/msg/tx/{id}

    message à émettre {"to":..,"msg":..}

  • RX
    mesh/nodes/{id}/status

    online/offline, retain=true (LWT)

  • RX
    mesh/nodes/{id}/stats

    RSSI, SNR, rx/tx, uptime, heap

  • RX
    mesh/nodes/discovery

    beacon d'un autre nœud (pour n8n)

Les gros messages passent par …/large/{from} en contenu brut, sans souci d'échappement JSON.

Gros messages, fragmentés

Au-delà de MESH_SINGLE_MAX (~100 o), le message est découpé en blocs de 48 o encodés base64, envoyés un par un au rythme de la file LoRa. Réassemblage par (expéditeur, id), l'ordre n'a pas d'importance.
